# ADR 0001: Базовая frontend-архитектура

## Статус

Принято

## Контекст

Relay Desk потребуются несколько страниц, типизированные продуктовые данные, формы, асинхронные состояния, адаптивный интерфейс и постепенно развивающиеся проверки поставки. Начальная кодовая база должна оставаться понятной во время онбординга и не должна заранее привязывать продукт к абстракциям управления состоянием или загрузки данных до появления реальной потребности.

## Решение

Использовать React с TypeScript и Vite. Для навигации по URL использовать React Router. Начать с локального типизированного API поверх демонстрационных данных и компонентных тестов на Vitest и Testing Library.

Не добавлять в начальную версию глобальное хранилище состояния, серверный frontend-фреймворк или универсальную библиотеку загрузки данных. Возвращаться к этим решениям только тогда, когда поведение продукта создаст конкретную проблему, которую текущий подход не решает достаточно чисто.

## Последствия

- Начальная архитектура достаточно компактна для сквозного изучения.
- Продуктовые страницы работают через асинхронную клиентскую границу, но настоящий HTTP и серверное хранение пока отсутствуют.
- Архитектурное развитие должно опираться на продуктовую причину, а не на желание расширить список технологий.
