# Функциональная и техническая приёмка baseline Relay Desk

Дата: 1 ноября 2026 года.

Основание: продуктовые требования baseline, архитектурная документация и фактические проверки приложения.

## Решение

Обязательные требования baseline выполнены и проверены. Relay Desk принимается как функциональная первая версия учебной frontend-песочницы. Настоящий backend, deployment и production-эксплуатация находятся за её границей.

## Основные исправления до принятия baseline

1. Матрица использует статус «пройдено» только при указанном проверяемом доказательстве.
2. Каталог показывает выбранную услугу, переносит её очередь, категорию, приоритет и шаблон в форму; полная статья базы знаний открывается отдельным маршрутом.
3. Поведенческие тесты покрывают каталог, знания, команду, отчёты, внутреннюю заметку, отмену, ошибки, сохранение, роли и клавиатурный фокус.
4. Жёстко заданные счётчики и отчётные значения заменены вычислениями из общего store.
5. Ошибка сохранения свойств отображается пользователю, форма остаётся доступной для повторной попытки.
6. Мутации сохраняются в versioned `localStorage` и восстанавливаются после перезагрузки.

## Фактически выполненные проверки

- `npm ci --no-audit --no-fund` — пройдено, 254 пакета.
- `npm run typecheck -- --force` — пройдено.
- `npm run lint` — ESLint и Prettier пройдены без warnings.
- `npm test -- src/api/relayDeskApi.test.ts src/App.test.tsx --reporter=dot` — 2 файла, 31/31 тест.
- `npm run build` — пройдено; 42 модуля, JS 334.61 kB (100.36 kB gzip), CSS 26.20 kB (6.11 kB gzip).
- `npm audit --omit=dev --json` — 0 уязвимостей production-зависимостей.
- `npm audit --json` — 12 moderate в dev-tooling ESLint/minimatch, 0 high, 0 critical.
- Browser, обычный viewport — каталог → создание `RD-143` → публичный ответ → внутренняя заметка → статус → исполнитель → новая вкладка; данные сохранились.
- Browser, база знаний — список → `kb-21` → полные разделы инструкции.
- Browser, сортировка — `priority_desc` отражён в URL и первой показана критическая заявка.
- Regression, SLA — показатель dashboard равен результату `/tickets?sla=overdue`; решённая `RD-119` исключена.
- Browser, связанные справочники — после выбора очереди «Рабочее место» доступны только категории «Оборудование» и «Офис и связь».
- Browser, 390×844 — страница не имеет горизонтального переполнения (`scrollWidth = 390`); навигация прокручивается внутри собственного контейнера.
- Browser console — 0 errors и 0 warnings в функциональной и мобильной сессиях.

## Граница первой версии

Сознательно не реализованы: настоящий backend и HTTP, реальная аутентификация, серверные права и аудит, синхронизация между браузерами/устройствами, вложения, уведомления, пагинация больших наборов, экспорт, SLA-календарь рабочего времени, оценка удовлетворённости, deployment и production observability.

## Оставшиеся ограничения и непроверенные области

- Полный audit показывает 12 moderate advisory только в dev-tooling; автоматического совместимого исправления без смены major-линии нет. Production dependency set чист.
- Специализированный автоматический accessibility-аудит (axe) и кроссбраузерная матрица не выполнялись.
- Автоматизированный Playwright suite не добавлен; ключевые E2E выполнены вручную в реальном Chromium-браузере, а критические контракты покрыты Vitest/RTL.
- Hosting, deployment, real network/API security и нагрузочные проверки не выполнялись.
