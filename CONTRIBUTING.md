# Участие в разработке

Relay Desk развивается через GitHub Issues, отдельные ветки и Pull Request. Рабочий язык задач, PR и ревью — русский.

## Получение проекта

```bash
git clone https://github.com/glvgvzh/relay-desk.git
cd relay-desk
npm ci
npm run dev
```

Используйте Node.js 24. Перед началом работы синхронизируйте локальную `main`:

```bash
git switch main
git pull --ff-only
```

## Работа с Issue

1. Прочитайте цель, контекст, критерии приёмки и ограничения задачи.
2. Уточните противоречия до реализации, если они меняют ожидаемый результат.
3. Создайте ветку от актуальной `main`, например `fix/search-query-sync` или `feature/filter-reset`.
4. Не смешивайте задачу с посторонним рефакторингом.

Не назначайте себе новую задачу только по названию: содержание Issue является источником требований.

## Коммиты

Используйте Conventional Commits: `fix:`, `feat:`, `test:`, `docs:`, `refactor:` или `chore:`. Сообщение должно описывать фактическое изменение. Не переписывайте общую историю без согласования.

Перед добавлением файлов в индекс или изменением истории проверяйте `git status`, `git diff` и, когда нужно, `git diff --staged`.

## Локальные проверки

Автор выбирает проверки пропорционально изменению и отвечает за их результат. Полный набор соответствует CI:

```bash
npm run typecheck
npm run lint
npm test
npm run build
```

Ошибки обязательного CI исправляет автор PR. Они не исправляются автоматически reviewer или другим участником.

## Pull Request

1. Опубликуйте ветку и откройте PR в `main`.
2. В описании кратко укажите изменение и свяжите PR с Issue, например `Closes #12`.
3. Дождитесь обязательного CI и code review.
4. Обновляйте тот же PR после замечаний; не открывайте новый без причины.

PR template намеренно не содержит чек-листа самопроверки: локальные проверки и исправление CI остаются ответственностью автора.

## Review и merge

Ревью сначала оценивает корректность решения и соответствие архитектуре, затем читаемость, тесты и детали реализации. Замечания помечаются как:

- **Блокирующее** — необходимо исправить до merge.
- **Необязательное** — улучшение или вопрос, который не блокирует текущую задачу.

Изменение попадает в `main` только через PR после успешного CI и устранения блокирующих замечаний. Прямые коммиты в `main` не являются обычным рабочим процессом.
